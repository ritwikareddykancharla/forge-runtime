Abstract

ForgeRuntime eliminates four structural bottlenecks in enterprise code-modernization and analytics agents: slicing multi-file Python repositories down to exact 2-hop caller/callee AST signatures (-83.2% prompt tokens at 100% recall), routing tasks by cyclomatic complexity and latency SLA across Bedrock tiers (-59.7% p50 latency), executing refactored code inside pre-warmed python3 -I worker pipes (0.63 ms warm vs 38.7 ms cold, 10/10 escape vectors blocked), and enforcing column-level PII/PCI permissions at SQLite compile time before any Apache Iceberg table row is read.

02Problem & AWS Team Alignment

Built directly for agentic modernization, developer runtime, and governed analytics workloads (AWS Transform, Velocity Labs, AWS Agentic AI, and Forward Deployed Engineering):

  • AST Call-Graph Slicing vs. Raw File Chunking (`forge_runtime/ast_graph.py`): Sending entire repositories burns 4,382 tokens per turn on unrelated methods, while naive single-file truncation captures only 20.5% of cross-file dependencies. Indexing directed CALLS, IMPORTS, and INHERITS edges emits full focal AST bodies (`Hop 0`) plus typed signatures (`Hop 1..2`), cutting prompt tokens by 83.2% (5.97x compression) at 100.0% 2-hop recall.
  • Pre-Warmed OS Worker Pool vs. Cold Subprocesses (`forge_runtime/cedar_sts_gate.py`): Keeping isolated python3 -I workers alive over persistent pipes lowers p50 dispatch from 38.7 ms to 0.63 ms (61.9x faster) while combining pre-flight AST validation, safe builtins, import allowlists, and a timeout watchdog to block 10/10 escape vectors.
  • Compile-Time PII/PCI SQL Governance (`forge_runtime/governed_lake_mcp.py`): Analytics agents routinely emit SELECT * or join sensitive customer columns. Registering SQLite's C-level set_authorizer (`SQLITE_READ`) alongside sovereign region CTE injection blocks unauthorized reads of email, ssn, and raw_card_token before execution while allowing aggregate ROAS queries.
