01 · Problem

Problem

Autonomous software modernization and developer productivity agents hit concrete systems failures on real multi-file repositories: cyclic module dependencies, non-idempotent retries after worker crashes, rubber-stamp unit tests, oversized prompts, cold sandboxes, and unguarded SQL queries.

Python 3.12 · Built-In Runtime Modules
01 · CYCLIC REPOS & ZOMBIE WORKERS

Single-File Edits Break Callers and Crashed Workers Duplicate Writes

Migrating upstream callers before leaf modules breaks contracts, mutual imports crash naive topological sorters, and mid-wave Lambda timeouts cause retried workers to double-publish side effects unless SQLite WAL fencing tokens and idempotent tool outboxes are enforced.

02 · RUBBER-STAMP AI UNIT TESTS

100% Line Coverage Hides 0% Bug Detection on Tautological Tests

LLM-synthesized unit tests frequently call target functions and assert isinstance(res, dict) or assert True, hitting 100.0% statement coverage while letting 16/16 off-by-one, sign, and boolean logic defects slip into production.

03 · BLOATED CONTEXT, COLD PIPES & SQL LEAKS

Whole-Repo Prompts Waste Budget and Regex SQL Filters Miss SELECT *

Dumping full repositories burns 4,382+ tokens per turn (while single-file context misses 79.5% of call contracts), cold subprocesses add 18.2 ms overhead per check, and naive SQL blocklists miss SELECT * leaks of customer emails and card tokens.

03 · Implementation

Implementation

Each subsystem in forge_runtime/ is built with Python's native ast, sqlite3 WAL, subprocess.run(..., shell=False), and hmac modules for deterministic execution and sub-millisecond verification.

6 Runtime Modules · Built-In Python Runtime
MODULE 01 · TARJAN-SCC WAVE TRANSFORM & WAL FENCING forge_runtime/transform_wave.py

TarjanSCCWavePlanner + FencedCheckpointStore + Self-Repair

Modernizing a multi-file codebase requires upgrading leaf helpers before upstream services, migrating mutually importing modules together as a single unit, and ensuring failover workers resume from the last checkpoint without duplicating side effects.
Tarjan O(V + E) + SQLite WAL Outbox: Collapses cyclic imports (auth/session_cache.py <-> auth/token_codec.py) into atomic SCC-02 across 4 waves (6 files, 10 → 0 legacy anti-patterns), enforces monotonic fencing_token leases (12/12 zombie writes rejected, 0 duplicate side effects across 12 crash trials), and lifts wave pass rate from 80.0% Pass@1 to 100.0% Pass@3 via unittest traceback self-repair.
MODULE 02 · AST MUTANT-KILL ADEQUACY VERIFIER forge_runtime/mutant_verifier.py

ASTMutantSynthesizer + Isolated subprocess.run(..., shell=False)

Line coverage only proves a test called a function, not that it checked the output. Injecting deliberate off-by-one, operator, and boolean mutations into the target AST proves whether the test suite actually catches real logic bugs.
5 AST Operator Classes: Synthesizes 16 single-defect mutants (<= → <, + → -, // → *, and → or, True → False, off-by-one thresholds) and executes candidate tests in credential-stripped python3 -I subprocesses: catching assert True suites (100.0% line coverage, 0.0% kill) and naive LLM tests (37.5% kill) while verifying survivor-guided boundary tests (100.0% kill, 3/3 gate accuracy).
MODULE 03 · AST REPO GRAPH & SLICER forge_runtime/ast_graph.py

ASTRepoGraph + 2-Hop Minimal Contract Packer

When modifying a single method, an engineer reads that method's full body plus the function signatures and docstrings of the helpers it calls, rather than thousands of lines of unrelated code. The AST slicer builds that exact prompt slice automatically.
Python ast BFS: Parses modules into 56 reference nodes and 38 directed CALLS, IMPORTS, and INHERITS edges (plus self-indexing ForgeRuntime v2's own 11 files, 227 nodes, and 337 edges). Bounded BFS (hop_budget=2) emits full source for Hop 0 and signature/type stubs for Hop 1 and Hop 2: 733.7 vs. 4,382 tokens (5.97×, -83.2%) at 100.0% recall.
MODULE 04 · SLA & BUDGET BEDROCK ROUTER forge_runtime/model_router.py · web_api.py

MultiModelRouter + Live Bedrock Synthesis

Quick IDE symbol lookups fit on sub-300 ms models, standard SQL patches fit on Sonnet, and multi-file refactors go to Opus, unless a strict latency or cost ceiling triggers an automatic step-down.
Structural Scoring: Scores cyclomatic branches, AST hop depth, files touched, and token volume to route across bedrock/amazon.nova-lite-v1 (4), bedrock/anthropic.claude-sonnet-4 (5), and bedrock/anthropic.claude-opus (3), cutting p50 latency -59.71% and cost -35.89% ($0.6069 vs. $0.9467, 12/12 accuracy).
MODULE 05 · CEDAR + STS OBO + WARM POOL forge_runtime/cedar_sts_gate.py

Cedar Policy Evaluator, STS Session Minter & python3 -I Pool

Destructive DDL actions stay blocked even for admin roles, and production patches require a verified human approval ticket. Authorized code runs inside pre-started isolated workers so test checks finish in under half a millisecond.
Cedar AST & Pipe IPC: Evaluates 5 Cedar policies with strict forbid > permit (4/4 invariants 100.0%), signs sts:TransitiveTagKeys via HMAC-SHA256, and dispatches AST-checked Python over persistent python3 -I pipes in 0.324 ms p50 (0.387 ms p95) vs. 18.200 ms cold spawn (56.2× speedup, 10/10 escapes blocked, automatic watchdog worker respawn).
MODULE 06 · 4-GATE ICEBERG / SQLITE MCP forge_runtime/governed_lake_mcp.py

SQLite C-Engine set_authorizer, Region RLS & Schema Pre-Check

Regex filters miss aliased joins and SELECT * queries. Hooking directly into SQLite's query compiler aborts compilation whenever a statement references a restricted email or card column, before any row is read.
4 Pre-Execution Gates: (1) Multi-statement & DDL/DML blocker (DROP, DELETE, ATTACH); (2) SQLite C-callback conn.set_authorizer enforcing PII_CONFIDENTIAL / PCI_RESTRICTED column clearances; (3) CTE rewrite WITH _rls AS (...) scoping regions (NA / EMEA); and (4) EXPLAIN QUERY PLAN catching nonexistent columns pre-execution (8/8 cases 100.0%).

TRADE-OFF 01 · TARJAN SCC + WAL FENCING

Atomic Cyclic Super-Nodes vs. Per-File Parallelism

Collapsing mutual imports via Tarjan's SCC requires co-migrating coupled files in a single wave prompt, trading fine-grained per-file concurrency inside cycles for zero mid-wave circular ImportError failures and deterministic SQLite WAL fencing-token replay.

TRADE-OFF 02 · MUTATION KILL vs. LINE COVERAGE

16 Subprocess Runs (~590 ms) vs. Catching Tautological Tests

Evaluating 16 AST mutants across 4 parallel python3 -I subprocess workers takes ~195–590 ms compared to a single 50 ms coverage pass, in exchange for catching 100.0%-coverage assert True suites that kill 0.0% of logic bugs.

TRADE-OFF 03 · WARM PIPES & SQL AUTHORIZER

38.5 ms Up-Front Warmup & Compiler Hooks vs. Cold Regexes

Booting persistent python3 -I workers pays a one-time 38.53 ms warmup to achieve 0.324 ms p50 dispatch (56.2× faster), while SQLite's C-level conn.set_authorizer blocks SELECT * PII leaks in 0.012–0.211 ms before execution.
